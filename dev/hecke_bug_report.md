# A reproducible assertion failure in Hecke's automorphism path

Found while stress testing the backtrack experiment against Hecke on randomly
generated lopsided lattices.  This is a bug in Hecke itself, independent of the
experiment, and the fix appears to be a few lines.

## Symptom

`automorphism_group_order` raises

    AssertionError: length(I) == length(II)

from `src/QuadForm/IntegerLattices/ZLatticeMorphism.jl:457`.

It is not rare on lattices with a wide spread of diagonal entries: of 379
random positive definite lattices of rank 3 to 7, built as `B * D * B^t` with
`B` unimodular with small off-diagonal entries and `D` diagonal with one or two
large entries, **26 raise it**.  The tuned invocation with `do_lll = false`
fails on 38 of the same 379, of which 12 are rescued by the default path.

## Two that reproduce it

Both are rank 6.  Generated with `MersenneTwister(20260825)`; the diagonal of
`D` is given, `B` has ones on the diagonal and entries drawn from `-2:2` off it.

    trial 284   D = [3, 300, 2, 2, 3, 3]    det 2073891600, diagonal 311..1243
    trial 370   D = [50, 11, 3, 3, 3, 1]    det  312221250, diagonal  21..235

The script that produced them is `dev/heckeerr.jl` in the experiment's working
directory; it can be reduced to a single Gram matrix if that is easier to work
with.

## What is happening

The code computes a bound on how many bits the entries of the extra Gram
matrices may have, so that the small-integer path cannot overflow:

    gramnbitsbound = bitbound - vectors_nbits - nrows_nbits - 1 - arangebit - nbits(length(res) - 1)
    I = collect(2:length(res))
    II = filter(i -> maximum(nbits, res[i]) <= gramnbitsbound, I)
    @assert length(I) == length(II)
    I = II

On a lopsided lattice the invariant Gram matrices coming from the projections
have large entries, some exceed the bit bound, and `II` is a proper subset of
`I`.  The assertion then fires.

The line immediately after the assertion, `I = II`, is already written to carry
on with the filtered set, and the commented-out block between them says what
was intended:

    #if maximum(nbits, res[1]) <= gramnbitsbound && length(II) < length(I)
    #  #error("Some Gram matrices are too large. Interesting case?!")
    #  @vprintln :Lattice 1  "Removed Gram matrices with entries too large"
    #end

So the assertion looks like a leftover marker for a case thought not to occur.
Dropping an invariant Gram matrix is sound -- it only weakens the pruning, it
cannot make the answer wrong -- provided at least the first form is kept, which
the guard in the commented block already checks.

## Suggested minimal change

Replace the assertion with the commented-out branch, so that a Gram matrix too
large for the small-integer path is dropped with a verbose note instead of
aborting the computation.  If dropping all of them is a concern, the condition
`maximum(nbits, res[1]) <= gramnbitsbound` in that branch is the check that the
first form itself still fits.

## Cross-check

On both lattices above the experiment returns order 2, with every generator
verified to satisfy `M G M^t = G`.  Order 2 is what one expects for a random
lopsided lattice, the group being generated by minus the identity.
